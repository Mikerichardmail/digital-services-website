# Digital Services Website: Master Plan

For building with **Google Antigravity**, versioned on **GitHub**, hosted on **Cloudflare Pages**, payments via **Razorpay Payment Links**.

Brand name, domain, WhatsApp number and email are placeholders: `[BRAND]`, `[DOMAIN]`, `[WHATSAPP]`, `[EMAIL]`. Put them in one config file (`src/data/site.json`).

---

## 0. Summary

- Original list (232) + easy tech help (100) + new ideas merged and deduplicated into **162 unique services** in **17 categories**.
- Monthly plans and Custom projects are **filtered views** of the same data, not separate categories (this removed most of the old duplicates).
- Minimum price on the whole site: **₹500**. Technical consultation: **₹1,500** flat.
- Target clients: local shops, restaurants, clinics, small businesses, startups, YouTubers/creators, app and website owners. Focus on NCR, serving all of India.

**Column guide for the service tables**

- **Price (₹):** "starting from" range. Display as "From ₹X".
- **Type:** One-time, Monthly, Custom.
- **Pay:** `Link` = fixed scope, buy with a Razorpay Pay Now button. `Quote` = get a quote on WhatsApp, then pay a 50% advance by manual payment link. `Sub` = monthly, needs Razorpay Subscriptions (not Payment Links). `Custom` = discuss first.

## 5. Tech stack and hosting

- **Framework:** Astro (static output) + Tailwind CSS. One data file generates all category, city and filtered pages.
- **Hosting:** Cloudflare Pages connected to the GitHub repo. Push to `main` and it deploys automatically.
- **Server code:** Cloudflare Pages Functions in `/functions/api/` (Razorpay calls, webhook).
- **Why not GitHub Pages:** static only (no place for the Razorpay secret), and its terms restrict sites focused on commercial transactions. Check GitHub's current terms.
- **Domain:** buy a `.in` or `.com`, point DNS to Cloudflare Pages.

## 6. Razorpay payment flow

1. Visitor clicks **Pay Now** on a `Link` service and fills a small form (name, phone, email, optional note).
2. Frontend calls `POST /api/create-payment-link` with `{ serviceId, name, email, phone }` (never send the amount).
3. The function looks up the price **server-side** from `services.json` (never trust a client-sent amount), then calls Razorpay `POST /v1/payment_links` using the key ID and secret.
   - `amount` is in paise (₹500 = 50000), `currency` is `INR`
   - include `description`, `customer`, `reference_id`, `notes` (serviceId), `callback_url` (`/thank-you`), `callback_method` (`get`)
4. The function returns `short_url` and the browser redirects to it.
5. Razorpay redirects back to `/thank-you` after payment.
6. **Webhook** `payment_link.paid` hits `/api/razorpay-webhook`. Verify the `X-Razorpay-Signature` HMAC-SHA256 of the raw body with the webhook secret before trusting it. Then notify you (email or WhatsApp) and log the order.

**Rules**

- `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET` live only in Cloudflare environment variables (and `.dev.vars` locally). **Never commit them.**
- Range-priced `Link` services: the Pay Now amount is the "from" price. Extra scope is billed later with a manual payment link. Button text: "Book from ₹X".
- `Quote` services: button = "Get Quote" (opens WhatsApp with the service name prefilled). You then create a 50% advance payment link in the Razorpay dashboard.
- `Sub` services: need Razorpay Subscriptions (separate setup). For launch, take monthly clients through WhatsApp and a manual first payment, then add Subscriptions later.
- Test everything in Razorpay **test mode** first, then switch to live keys.
